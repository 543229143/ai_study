# 工程守则（给 AI 代理读）

本项目由 AI 代理参与开发。以下规则优先于任何单轮指令。
违反规则的产出，即使代码能跑，也不算完成。

## 开始之前

1. 先读 `docs/plan.md`，确认当前这一片是哪一条验收项（项目有 `README.md` 也一并读）。
2. 只做「已知缺口」之前的第一条 `- [ ]`，或用户本轮明确指定的那一条。缺口里的条目不要顺手做。
3. 不确定边界时，先问，不要自行扩大范围。

## 切分

- 一次只做一片。一片 = 能在一次会话内完成、能独立验证的最小改动。
- 一片完成后立刻记录并提交，不要攒着做下一个。
- 需要跨多个模块的大改，先拆成多片写进 `docs/plan.md`，再逐片做。
- 不做与本片无关的重构、格式化、依赖升级；要做就单独立项。

## 验收

**完成的定义：判定证据 + 记录 + 签字，三者缺一，状态就是「未验证」。**

- 「未验证」是合法状态，写它不算失败。
- 声称「已完成」但拿不出证据，按**未完成**处理，不按说谎处理——补证据即可。
- 每片的证据必须是命令 + 输出 + 结果，别人能照着重跑。
- mock 测试、类型检查通过、截图好看，都不算真实验收，除非这一片的验收标准就是它。
- 失败、跳过、超时、临时绕过，必须原样记录，不许抹平。

## 停止

出现任一信号就停，不要「再试一次」：

| 信号 | 判据 |
| --- | --- |
| 原地打转 | 同一个失败签名重复出现，且没有提出新假设 |
| 越修越糟 | 本次修复引入的新问题多于原问题 |
| 严重超时 | 超过本片预估时间 2 倍 |

停止时必须输出：现象、已排除的原因、怀疑位置、建议下一步。
不许删测试、放宽断言、跳过用例、注释检查来换取通过。

## 边界

- 不碰生产环境、生产数据、生产凭证。
- 不提交任何凭证、私钥、真实用户数据、原始日志。
- 不擅自改 CI/CD、发布流程、权限配置。
- 临时文件、试验产物放 `tmp/` 或 `.local/`（需被 gitignore）。

## 结束每片时必须写

1. `docs/plan.md`：把本条改成 `- [x]`，在「已完成」加一行指向 checkpoint。正文不要写进 plan.md。
2. 新建 `docs/checkpoints/<编号>.md`。有 `docs/templates/checkpoint.md` 就照它写，否则写下面五栏：
   - 改了什么（文件 + 意图）
   - 怎么验的（命令 + 关键输出）
   - 没做什么 / 已知缺口
   - 剩余风险
   - **下一步**（一条，具体到能直接开工）

## 语言

- 代码注释、提交信息、文档默认中文。
- 提交信息用 `feat:` / `fix:` / `docs:` / `refactor:` / `test:` 前缀。
