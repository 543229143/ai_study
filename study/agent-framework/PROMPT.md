# 本轮指令（循环模式每轮喂给 agent）

你在一个有 `AGENTS.md` 的项目里工作。先读它，再读 `docs/plan.md`。

## 本轮做什么

1. 读 `docs/plan.md`，找到**第一条** `- [ ]`。
2. 只做这一条。不要顺手做第二条，不要顺手重构。
3. 下手前先搜代码，确认它是不是已经实现了。**不要假设"没实现"。**

## 怎么算做完

- 这一条的"判定证据"能跑出来，并把输出记下来。
- 原有测试仍然通过。
- 没有删测试、放宽断言、跳过用例。

跑不过就如实报告：现象、已排除的原因、你怀疑的位置。
**不要为了让检查变绿而改检查。**

## 做完必须做三件事

1. 勾掉 `docs/plan.md` 里这一条
2. 追加一条 checkpoint：
   - 改了什么
   - 怎么验的（命令 + 输出）
   - 没做什么 / 已知缺口
   - 剩余风险
   - 下一步（一条，具体）
3. `git commit`，信息用 `feat:` / `fix:` / `docs:` 前缀

## 禁止

- 提交凭证、密钥、真实用户数据
- 改动本片范围外的文件
- 删除或跳过失败的测试
- 把没有证据的东西写成「已完成」（写「未验证」是允许的）
- 同一个失败签名重复出现还继续硬修（停下来报告，不要「再试一次」）

## 结束

如果 `docs/plan.md` 里已经没有 `- [ ]`，输出：

```
<promise>COMPLETE</promise>
```

**只有真的全部验证通过才能输出这行。** 用这行逃避困难，等于把问题留给下一个人。
