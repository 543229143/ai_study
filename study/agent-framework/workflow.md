# 一轮的完整时序

每片活都走这条线，不跳步。中断后从"读 plan"这一步恢复。

```
定向 → 选片 → 实现 → 验证 → 记录 → 闸门 → 下一片
```

## 0. 定向（人）

- 读 `docs/plan.md`：还剩哪些 `- [ ]`
- 读上一条 checkpoint 的"下一步"
- 决定这一片做哪条（`plan.md` 第一条，或临时插入）

产物：一句话说明本轮目标。不写就别开工。

## 1. 选片（人 + agent）

- 从 `plan.md` 取一条，复制成任务卡（母本 `templates/task-card.md`，装进项目后是 `docs/templates/task-card.md`）
- **只有半天以上的片才展开任务卡**；1 小时内的片，plan 里那一行就是卡
- 确认三件事：
  - 目标能用一句话说清
  - 完成判定是**可执行的命令或可观察的现象**
  - 边界明确（哪些文件/模块不许碰）

产物：任务卡（放在对话里或 `docs/tasks/<编号>.md`）。

**起草可以交给 agent，拍板必须是人。** 尤其「完成判定」和「禁止碰」两栏——
验收标准不能由被验收方单方面定义。

**写不出完成判定的，退回重切，不要开工。**

## 2. 实现（agent）

- 只改任务卡允许的范围
- 小步提交：能跑通一个子步骤就提交一次
- 遇到与任务卡冲突的现实（接口不存在、依赖缺失）：停下来报告，不改任务卡自说自话

产物：代码 + 提交。

## 3. 验证（agent 跑，人看结论）

按任务卡里的"验证命令"执行，至少包含：

| 层级 | 例子 |
| --- | --- |
| 能跑 | 启动、编译、导入不报错 |
| 正确 | 针对性测试通过，边界用例通过 |
| 不回归 | 原有测试仍通过 |
| 真实 | 在接近真实的环境跑一次（容器/真实库/真实 CLI） |

**把输出原样贴进 checkpoint，不要只写"通过"。**

## 4. 记录（agent）

按 `templates/checkpoint.md` 写到 `docs/checkpoints/<编号>.md`（装进项目后模板在 `docs/templates/checkpoint.md`）：改了什么、怎么验的、没做什么、风险、下一步。

同时更新 `docs/plan.md`：勾掉本条，在「已完成」加一行指向 checkpoint。正文不要写进 plan.md。

产物：checkpoint + plan 更新 + 提交。

## 5. 闸门（人）

人只看四件事：

1. 证据是否对得上任务卡的完成判定
2. 有没有偷偷放宽验收
3. 有没有超范围改动（`git diff --stat` 对一眼）
4. 剩余风险是否可以接受

结论只有三种：**通过**、**退回重做**、**降级为部分通过并记录缺口**。

**不签字不进下一片。** 这是整套框架唯一的强制点。

## 6. 下一片

- 通过 → 回到第 0 步
- 退回 → 同一条重做，不许换题
- 降级 → 缺口写进 plan 成为新的一条 `- [ ]`

---

## 中断恢复

会话断了、机器重启了、上下文被压缩了，按这个顺序恢复：

1. `git log --oneline -5` 看最后做了什么
2. 读最后一条 checkpoint 的"下一步"
3. 读 `docs/plan.md` 当前未勾选项
4. 确认工作区干净（`git status`），然后开工

**只要这三样在，就不需要"回忆上次聊到哪"。**

---

## 什么时候可以开循环

同时满足才考虑脚本循环（`scripts/loop.sh`）：

- 手动跑过至少 3 片，节奏顺
- 每片的验证命令是确定的、秒级到分钟级
- 仓库干净、有测试、分支不是 main
- 有人能定期看结果

否则就手动推。**循环放大的是流程质量，不是模型能力。**
